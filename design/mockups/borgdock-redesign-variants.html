Seven ways to reorganise what BorgDock does.

BorgDock does five things: it watches pull requests and their checks, tells you what needs you, hands failures and reviews to an agent, lets you review and merge without leaving, and ties all of that to work items. Each mockup below takes one of those jobs as its organising idea and rebuilds the window around it. The current tokens, chips and rings are not a constraint here. Every mockup is live: hover, click, drag, press keys.

Workbench: list plus inspector, nothing opens a window Briefing: Focus as an inbox you can clear Pulse: what changed since you last looked Timeline: PRs by recency, checks and logs in place Board: columns by what is blocking Deck: one review at a time Thread: work item, pull request, agent, next step

Direction 1Workbench

The idea: you never leave the list. Today a PR's checks, log and actions live in a separate detail window; here they live in an inspector beside the row you picked, so comparing two PRs is one click each. Every action is also a command: press ⌘K or Ctrl K while this window is in view. Checks read as a six-segment glyph, so a failing build is visible before you read a word.

    Direction 2Briefing

    The idea: Focus is an inbox, and an inbox should be clearable. It opens with a sentence that says what is on your plate and why, then a short stack of cards you can approve, skip or act on without opening anything. Every decision has Undo, so acting fast is safe. When the stack is empty it says so, instead of showing the same six PRs as the other tab.

    Direction 3Pulse

    The idea: a poller knows exactly what changed since you last looked, so show that instead of the whole list every time. Events are grouped by PR and each carries its own action: a failed check offers Fix with Claude, a review request offers Review, a finished agent offers its thread. Mark a group seen and it leaves. The light behind the glass is the state of the queue: rose while something is failing, amber while an agent is on it, teal when all is well. Try Fix with Claude on the first group.

    Direction 4Timeline

    The idea: the question is usually "what moved recently", so order by recency and put the checks and the first failing log line in the row itself. Every PR is a node on a rail whose ring fills with passing checks. Line counts become a two-tone bar so you compare churn at a glance. Click a row to open it in place. Fix, Rerun and Checkout are right there, so a failed build is two clicks from being handed to Claude.

    Direction 5Board

    The idea: sort by what is blocking, not by repository. Three columns say who the ball is with: you, someone else, or nobody (ready to merge). Drag a card to override the automatic placement when you know better. Merge lives on the card, and merged PRs count themselves into a small tally so the day has a visible end.

    Direction 6Deck

    The idea: reviewing is a sequence of single decisions, so show one PR at a time with everything needed to decide: description, branch, size, checks and the key hunk. Approve sends the card right, Review later sends it left, and the next one rises. Use the buttons or → ← while this window is in view. This would replace the Quick Review overlay's file-by-file walk for small PRs.

    Direction 7Thread

    The idea: BorgDock is the only tool that knows the whole chain, from an Azure DevOps work item to its pull request to the agent working on it. So organise around the chain. Pick a work item on the left and the right side shows the item, its PR with checks, the agent session with its last message, and a single "next step" that BorgDock computes. Pick the bug without a PR and press Start an agent.

    What the seven have in common

    Whichever direction wins, these decisions carry over. The functional ones matter more than the visual ones.

    Actions live on the thing

    Fix, Rerun, Review, Merge and Open in T3 sit next to the check, the review request or the PR they apply to. No hover pill bar, no context menu hunting.

    The next step is computed, then shown

    BorgDock already scores merge readiness. Every direction turns that score into a sentence or a placement ("Needs you", "Ready to merge", "Wait for the agent") instead of a number in a ring.

    One window, in place

    Inspectors, in-row expansion, sheets and card stacks all replace pop-out detail windows for the common case. Pop-outs stay for the diff and the SQL tool.

    Every fast action has Undo

    Approve, Skip, Mark seen and Merge are one click and reversible for a few seconds, so triage can be quick without being risky.

    Agents are first-class rows

    A running Claude or T3 session shows up where its PR is, with its last message, instead of as a strip under a row.

    Keyboard for the whole loop

    Command palette, J and K, arrows and Enter cover everything the mouse does. The status bar teaches the keys for the current view.

    Visual decisions that carry over

    Sentence case, no eyebrows

    Group labels like "Needs your review" replace tracked-out capitals. Counts sit next to the label in a lighter weight instead of a pill.

    One accent, used for one thing

    The accent marks selection or the single primary action. Status has its own three colours and never borrows the accent.

    Numbers become shapes where they can

    Pipeline segments for checks, a two-tone bar for line counts, a ring for readiness. Numbers stay where a number is the answer.

    Monospace only for code

    The status bar, PR numbers and counts move to the UI face with tabular figures. Logs and diffs keep JetBrains Mono.

    Motion answers you

    Nothing animates on its own except the aurora and running checks. Everything else moves because you clicked, dragged, filtered or approved.

    Reduced motion is a first-class path

    All transitions collapse to instant under the OS setting or the toggle at the top of this page. The layouts never depend on animation to be understood.
