How it behaves

  • Opens after 300 ms on the check bar (not the whole row, so skimming the list doesn't pop cards). Stays open while the pointer is on the bar or the card; Esc closes it. Click on the bar still opens the PR on the Checks tab.
  • Names and states come from the PR poll (ciJobs, failing and pending names), so the list shows instantly. The reason comes from the CI failure store's signals for the failed job; if that job's log hasn't been read yet, the hover reads it (tail only, same ci_read_job_log path) and the skeleton fills in.
  • Per failing job: the failed step, the first failing test or error with expected/received and file:line, then "+N more". Totals line ("3 failed, 412 passed") comes from the summary signal.
  • Shared failures (also red on master) get the amber "Not caused by this PR" line with owner, same wording as the row's marker.
  • Passed and skipped stay one compact line each; a long list scrolls inside the card past ~460 px.
  • Buttons reuse what exists: Rerun failed (check suite rerun) and Fix with agent (fixWithClaude, which runs the launch guard first).
