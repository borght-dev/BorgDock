# Bun Migration & Frontend Modernization

**Date:** 2026-05-07
**Status:** Design approved
**Scope:** Single PR

## Goal

Replace npm with bun across both JS projects in the repo, unify them under a bun workspace, drop now-unnecessary tooling (`tsx`, the manual `optionalDependencies` block), enable the React Compiler, and add lefthook pre-commit checks.

## Current state

- **Two npm projects**, each with its own `package-lock.json`:
  - `src/BorgDock.Tauri/` — Tauri 2 + React 19 + Vite 8 + Vitest 4 + Storybook 10 desktop app
  - `site/` — Astro marketing site
- **Three CI workflows** use npm: `.github/workflows/test.yml`, `release-tauri.yml`, `deploy-site.yml`
- **`tsx`** in devDeps purely to run TS scripts (`scripts/changelog/validate-release.ts`)
- **`optionalDependencies` block** in `src/BorgDock.Tauri/package.json` pins ~60 platform-specific binaries — a workaround for npm 7's cross-platform lockfile bugs
- `bun 1.3.10` already installed locally
- React 19.2.6 in use; no React Compiler yet
- No git hooks installed

## Out of scope

- Migrating off `vitest` (e.g. to `bun test`) — vitest 4 + jsdom is already fast and the integration with `@testing-library/react` is mature
- Replacing `biome` with `oxlint` — biome already covers lint + format
- Deleting existing `useMemo` / `useCallback` calls — React Compiler makes them often-redundant but they're still correct. Opportunistic cleanup later
- Renaming/moving `src/BorgDock.Tauri/` or `site/` directories — high blast radius for no real win

## Design

### 1. Bun migration

**Lockfiles:**
- Delete `src/BorgDock.Tauri/package-lock.json` and `site/package-lock.json`
- Single `/bun.lock` (text format, default in bun 1.2+) at repo root

**Package.json changes:**
- New `/package.json` at repo root (see §2 Workspace)
- `src/BorgDock.Tauri/package.json`:
  - Remove `tsx` from devDeps
  - Change `validate-release` script: `tsx scripts/changelog/validate-release.ts` → `bun scripts/changelog/validate-release.ts`
  - Remove the entire `optionalDependencies` block (see §3)

**CI workflows** — all three files swap:
```yaml

    node-version: '22'
    cache: 'npm'

- uses: oven-sh/setup-bun@v2

    bun-version: '1.3.10'
- run: bun install --frozen-lockfile
- run: bun --filter borgdock build
```

### 2. Workspace unification

**New `/package.json`:**
```json
{
  "name": "borgdock-monorepo",
  "private": true,
  "workspaces": ["src/BorgDock.Tauri", "site"],
  "packageManager": "bun@1.3.10",
  "scripts": {
    "postinstall": "lefthook install",
    "dev": "bun --filter borgdock dev",
    "build": "bun --filter borgdock build",
    "test": "bun --filter borgdock test",
    "lint": "bun --filter borgdock lint",
    "tauri": "bun --filter borgdock tauri",
    "site:dev": "bun --filter borgdock-site dev",
    "site:build": "bun --filter borgdock-site build"
  },
  "devDependencies": {
    "lefthook": "^1.7.0"
  }
}
```

Workspace `name` fields confirmed: `src/BorgDock.Tauri/package.json` is `borgdock`; `site/package.json` is `borgdock-site`. Both filter targets above are correct.

**Hoisting:** node_modules hoists to root by default with bun workspaces. Verified compatible with: Vite 8 (uses `node_modules` resolution), Vitest 4 (same), Tauri CLI (locates `package.json` upward), Storybook 10 (workspace-aware), Playwright (workspace-aware).

**Workspace member package.jsons** keep their own scripts unchanged. From inside `src/BorgDock.Tauri/`, `bun run dev` still works exactly the same — bun resolves the local script.

### 3. Slim `optionalDependencies`

Remove the entire block from `src/BorgDock.Tauri/package.json`. The platform binaries (`lightningcss-*`, `@swc/core-*`, `@biomejs/cli-*`, `@tauri-apps/cli-*`, `@rolldown/binding-*`, `@tailwindcss/oxide-*`, `@unrs/resolver-binding-*`) are declared as optional deps by their parent packages. Bun's lockfile records the resolved platform-correct entries per-platform, so cross-platform CI works without the manual pinning.

**Verification:** all three CI runners (macOS, Windows, Linux) succeed at `bun install --frozen-lockfile` + build. If a specific platform fails, restore just the failing platform's entries — don't restore the full block.

### 4. React Compiler

**Install:**
```
bun add -D babel-plugin-react-compiler --filter borgdock
```

**`src/BorgDock.Tauri/vite.config.ts`** — modify the `react()` plugin invocation:
```ts
import react from '@vitejs/plugin-react';
// ...
plugins: [
  react({
    babel: {
      plugins: ['babel-plugin-react-compiler'],
    },
  }),
  // ...rest
]
```

`@vitejs/plugin-react` v6 uses Babel by default (the SWC variant is `@vitejs/plugin-react-swc`), so this is the correct integration point.

**Behavior:** Compiler auto-memoizes function components and hooks. Runtime semantics are unchanged for correct React code. Existing `useMemo`/`useCallback`/`memo` calls remain valid (often redundant, but harmless).

**Escape hatch:** add `"use no memo";` as the first directive in any file that misbehaves. Document this in `src/BorgDock.Tauri/CLAUDE.md` so future debuggers find it.

**Validation:** after enabling, profile the existing `WorkItemsSection` tree and the PR list — both heavily memoized — and verify with React DevTools that compiled components show the auto-memo marker. Existing tests must remain green.

### 5. lefthook pre-commit

**`/lefthook.yml`:**
```yaml
pre-commit:
  parallel: true
  commands:
    biome:
      glob: "src/BorgDock.Tauri/src/**/*.{ts,tsx,js,jsx,json}"
      run: cd src/BorgDock.Tauri && bunx biome check {staged_files}
    typecheck:
      glob: "src/BorgDock.Tauri/src/**/*.{ts,tsx}"
      run: cd src/BorgDock.Tauri && bunx tsc --noEmit
```

`tsc --noEmit` is project-wide (no per-file mode); the glob just gates whether the hook runs at all when relevant files are staged.

`postinstall: lefthook install` in root `package.json` wires hooks into `.git/hooks/` automatically after `bun install`.

**`.gitignore`:** no change needed — `lefthook` writes into `.git/hooks` which is already untracked.

## Verification plan (must run before merge)

1. From clean clone: `bun install` → populates root `node_modules`, exits 0
2. `bun run build` (root) → tsc + vite build green
3. `bun run test` → vitest green
4. `bun run lint` → biome clean
5. `bun --filter borgdock test:e2e` → Playwright green (auto-spawns `bun run dev`)
6. `bun run site:build` → Astro green
7. From `src/BorgDock.Tauri/`: `bun run tauri dev` → app launches, sidebar renders, no console errors
8. From `src/BorgDock.Tauri/`: `bun run tauri build` → produces signed installer (macOS) / MSI (Windows)
9. Stage a trivial edit, `git commit` → lefthook runs biome + tsc, blocks bad code, allows good code
10. Push to PR branch → all 3 GitHub Actions workflows green on macOS-latest, windows-latest, ubuntu-latest
11. With dev server running, open React DevTools → confirm a memoized component shows the React Compiler marker

## Risks & rollback

| Risk | Mitigation |
|---|---|
| Cross-platform CI fails after dropping `optionalDependencies` block | Restore just the failing platform's entries; don't revert the bun migration |
| React Compiler breaks a specific component | Add `"use no memo"` directive at the top of that file; report upstream |
| Tauri CLI behaves differently with hoisted node_modules | Tauri CLI doesn't care about hoisting; it locates `tauri.conf.json` via `--config` or cwd. If anything breaks, set `nohoist` for `@tauri-apps/cli` in root `package.json` |
| lefthook breaks contributor workflow | `LEFTHOOK=0 git commit ...` bypasses hooks for emergencies; documented in CLAUDE.md |
| `bun pm pack` behaves differently than `npm pack` for tree-sitter grammar source builds | Tested against the `tsx` grammar build during verification step before merge |
