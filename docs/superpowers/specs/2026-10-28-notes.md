# Notes: the rules

Notes are Obsidian-style markdown inside BorgDock: a vault of `.md` files, `[[links]]` between them,
and references to the pull requests, work items, T3 threads and workstreams BorgDock already knows,
shown with their live state. This file lists the decisions and the rules the code keeps. Change a
rule in its code and in this file together.

The File Palette and File Viewer go first; Notes takes over their hotkey (`Ctrl+F8`) and keeps
their full-text search (`content_search.rs`).

## Decisions (2026-10-28)

| Topic | Decision |
| --- | --- |
| File Palette | Remove both windows, their settings, capabilities and hotkey. Keep `content_search.rs` for note search. |
| Storage | Markdown files in a vault. Obsidian, VS Code and agents open the same files. |
| Vault folder | `<sync folder>/BorgDock Notes/` (the folder Workstreams uses, `settings.workstreams.folder`); without one, `%APPDATA%/BorgDock/notes/`. |
| Shape | A Notes section on the rail, plus a Notes tab on PR, work item and workstream detail. |
| Links | Notes with backlinks, pull requests, work items, T3 threads, workstreams, tags and properties, mentions on the other side. |
| Link syntax | Short refs where one exists (`AB#48213`, `planner#1412`). |
| Editor | Live preview: CodeMirror 6 renders markdown in place, raw syntax only on the cursor's line. |
| Daily | Daily note, yesterday's activity written in, quick capture on `Ctrl+F8`, tasks across notes, templates. |
| Agents | Start a T3 thread from a note, notes in Fix / Resolve prompts, vault path in prompts, thread results written back, workstream decisions as notes. |
| Graph | A local graph of the open note in the first version. |

## The vault

- One note is one `.md` file, UTF-8 with LF line endings. Its title is its file name without
  `.md`, as in Obsidian. Frontmatter (YAML between `---` lines) is optional.
- Folders are yours. BorgDock creates only `Daily/`, `Templates/`, `Decisions/` and `Inbox.md`, and
  only when a feature first needs them.
- BorgDock skips dot-folders (`.obsidian/`, `.git/`, `.trash/`) and reads only `.md` files.
  Other files are attachments: linked, never parsed.
- **Files are the truth; the index is disposable.** Links, tags, tasks and mentions live in an
  in-memory index (`services/notes/vault-index.ts`) rebuilt from the files at start. The main
  window lists the vault every 4 s (`runtime/notes-sync.ts`) and reads only files whose size or
  modified time moved; other windows do the same every 15 s while they show notes
  (`hooks/useNotesVault.ts`). Nothing BorgDock derives is written into the vault.
- **Never write over a change you haven't read.** Every write (the editor's autosave, a rename
  rewriting links, a task ticked from a list, an agent writeback) compares the file on disk with the
  content it last read. If they differ, the write stops and the editor shows "Changed on disk" with
  reload or keep mine. Writes are atomic (temp file, then rename), like workstreams.
- A sync client's conflict copy (`Note-PC.md`) is an ordinary note. BorgDock does not merge text.

## Links (`[[` and short refs)

| Written as | Resolves to | Rendered as |
| --- | --- | --- |
| `[[Note]]`, `[[Note\|label]]`, `[[Note#Heading]]` | the note with that file name, case-insensitive; shortest path wins when two folders hold the same name (Obsidian's rule) | a link; clicking one that names no note creates it |
| `AB#<id>` | `ado:<organization>#<id>`, the configured organization | a chip: type, state |
| `owner/repo#<n>`, or `repo#<n>` when one configured repository has that name | `gh:github.com/<owner>/<repo>#<n>` | a chip: checks, review state |
| `[label](t3code://threads/<environmentId>/<threadId>)` | `t3:<environmentId>/<threadId>` | a chip: Working / Your turn; click opens the thread in T3 |
| `[label](borgdock://workstreams/<id>)` | the workstream | a chip with its name |
| `#tag` (not all digits), `tags:` in frontmatter | a tag | a tag pill, filterable in the list |

- A bare `#123` is not a reference: it would collide with tags and has no repository.
- T3 threads and workstreams have no short form, because their names change. The editor inserts the
  stable address through autocomplete, so you never type an id; the label is only text.
- Identity is the `RefKey` Workstreams use (`services/workstreams/identity.ts`); a workstream is
  `ws:<id>` in the index. A workstream lists a note as a link member whose address is
  `borgdock://notes/<vault path>`, which opens in the Notes section. Chips read the stores BorgDock
  already polls (`services/notes/chips.ts`); a note never stores a title, state or check.
- Pull request and work item addresses (`https://github.com/…/pull/12`,
  `https://dev.azure.com/…/_workitems/edit/12`) count as mentions too; the editor draws them as
  links, not chips.
- Renaming a note rewrites `[[Old]]` in the notes that link to it, under the write rule above.
- **Mentions on the other side.** PR detail, work item detail and workstream detail get a Notes tab:
  the notes whose index holds that `RefKey`, and "New note for this", which creates a note with the
  reference in its first line.

## The Notes section

- Section 8 on the rail, key `8`. Left: folders and notes. Middle: the editor. Right: linked
  mentions (notes that link here), the references in this note, and the local graph.
- `Ctrl+O` in the section opens a quick switcher over note titles. Full-text search runs
  `search_content` over the vault.
- The editor is CodeMirror 6 with `@codemirror/lang-markdown`. Decorations render headings, lists,
  tasks, links and chips in place; the line holding the cursor or selection shows raw markdown.
- Autocomplete: `[[` (notes, then threads and workstreams), `AB#`, `#` (tags), `/` (templates).
- Autosave 500 ms after the last keystroke, and when you switch notes or close the window.
- **Local graph:** the open note and everything within two links (notes, PRs, items, threads,
  workstreams). No vault-wide graph in the first version.

## Daily notes, capture, tasks, templates

- **Daily note:** `Daily/YYYY-MM-DD.md`, created the first time something opens it: Focus, the
  section, or a capture. A `Templates/Daily.md` is its starting text when present.
- **Since yesterday:** when BorgDock creates a daily note, it writes one block from the Activity
  journal (merges, state moves, finished threads, failed checks) since the start of the previous
  daily note's day, at most a week back, between `<!-- borgdock:since <day> -->` markers. Written
  once, at creation. A note created on another machine already exists, so it gets no second block.
- **Quick capture (`Ctrl+F8`):** a small window like the palettes (`note-capture`). Enter appends
  `- HH:MM <text>` under `## Captured` in today's note, followed by a reference to the PR or work
  item last shown in a detail view (main window or pop-out) within two hours. Shift+Enter adds a
  line; Esc closes.
- **Tasks:** every `- [ ]` line in the vault, in one list in the section, grouped by note. Focus shows
  the count. Ticking one there edits its source line under the write rule.
- **Templates:** `Templates/*.md`, offered by `/` in the editor. Placeholders: `{{date}}`, `{{time}}`,
  `{{title}}`.

## Agents

- **Start a T3 thread from a note:** the note (or the selection) is the first message. The thread's
  address is appended to the note under `## Threads`. It starts the way Dispatch runs do (slot, model).
- **Thread results written back:** when a thread started from a note settles, its last agent message
  is appended under `## Agent notes`, inside `<!-- borgdock:agent <threadId> -->` markers, once per
  message id. This is the only place BorgDock writes text you did not type; it never edits outside
  its markers.
- **Notes in Fix / Resolve prompts:** the prompt file for a PR lists the notes that mention it, path
  and content.
- **Vault path in prompts:** every prompt BorgDock writes names the vault folder, so agents read and
  write notes with their own file tools.
- **Workstream decisions as notes:** deciding a workstream decision creates
  `Decisions/YYYY-MM-DD <question>.md` with the choice, what was set aside, the reason and a link
  back; the workstream gets the note as a context link member (`borgdock://notes/…`).
- Threads started from a note are followed from `localStorage` (`borgdock.notes.threads`) for two
  weeks; when one stops and waits, its last message is read at most once a minute.
